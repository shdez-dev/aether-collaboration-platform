# Cierre y aprendizaje

## Cerrar es una decisión de producto

Cerrar significa determinar qué se entregó, quién lo aceptó, qué falta y quién mantiene el resultado. Marcar todas las tarjetas como completas no demuestra utilidad, calidad o aceptación.

El código dispone de estados de cierre, hitos, documentos e historial. No se certifica mediante esta revisión un circuito integral de aceptación de entregables y seguimiento posterior. Esta nota define ese objetivo.

## Expediente de cierre

| Elemento | Contenido requerido |
| :--- | :--- |
| Resultado | Qué cambió respecto de la situación inicial |
| Entregables | Identificador, versión, criterio y aceptación |
| Desviaciones | Diferencias de alcance, fecha o recursos y su causa |
| Pendientes | Compromisos transferidos con responsable y vencimiento |
| Continuidad | Persona que operará o mantendrá el resultado |
| Aprendizaje | Supuestos confirmados, refutados y recomendaciones |
| Accesos | Personas que conservan consulta y plazo |
| Seguimiento | Indicador, fecha y responsable de medición |

## Flujo objetivo

1. El líder solicita cierre con las evidencias pertinentes.
2. El sistema comprueba entregables, observaciones críticas y pendientes.
3. El aprobador acepta o devuelve con criterios concretos.
4. La aceptación registra versión del expediente, actor y fecha.
5. Se ajustan capacidad y compromisos futuros de los participantes.
6. Se preservan documentos e historial bajo política de conservación.
7. Se programa una revisión de resultados si el valor aparece después.

Un cierre cancelado registra trabajo aprovechable y obligaciones pendientes. No se cuenta como proyecto completado con éxito. Un proyecto sustituido enlaza el expediente sucesor sin duplicar resultados en los reportes.

## Seguimiento posterior

Entregar una herramienta, una propuesta o un proceso no demuestra que se utilice. El seguimiento mide adopción, resultado o impacto con el beneficiario. Si no hay medición disponible, el tablero debe mostrar «resultado no medido».

Una revisión puede concluir que el proyecto entregó correctamente, pero no produjo el resultado esperado. Esa distinción es valiosa para aprender y no debe ocultarse cambiando retroactivamente el alcance.

## Archivo y eliminación

Archivar reduce actividad y puede restringir edición. Eliminar destruye o anonimiza información según una política explícita. El producto debe presentar el efecto de ambas acciones y evitar que archivar dispare cascadas de eliminación.

La conservación del historial y la eliminación de datos personales requieren una política conjunta: referencias estables, mínima información personal y trazabilidad de operaciones autorizadas. Los plazos concretos dependen del despliegue y deben definirse antes de comercializar.
